## Findings

1. **blocker** — `Sources/OpenUsage/Views/WidgetGroupedListView.swift:256`: on a merged card the row still gets `resetClaims[providerID]`, where `providerID` is the base account (`claude` / `codex`), while the merged Rate Limit Resets row lists the expiries of every account (`AccountMerge.swift:78` concatenates `expiriesAt`, `.values` sums the count). Scenario: work (`claude`, base) and home (`claude@…`) both on, home has a reset credit; the user opens the resets popover on the merged card and clicks "Use" on home's credit; the claim runs through work's `ClaudeResetClaimService`, so it either uses work's credit (an irreversible action on the wrong account) or fails. When the base account is turned off, the claim still goes to that turned-off account. Fix: give merged cards (`!group.accounts.isEmpty`) no claim service so the timeline is read-only, or route each expiry to its own account's service. Add a test for it.
2. **major** — `Sources/OpenUsage/Models/AccountMerge.swift:18`: `MergedAccount.shortName` cuts at the first `@`, which breaks the real Swap display names. Probe: `"Claude: Acme Org (alice@x.com)"` gives `Acme Org (alice`, `"Codex: work (bob@x.com)"` gives `work (bob`, `"Codex: Workspace ab12cd34 (bob@x.com)"` gives `Workspace ab12cd34 (bob`. Only the hub (`Claude: alice@x.com (Hub lab)`) and plain-email shapes come out right, and those are the only ones the tests use. Fix: drop a trailing ` (…)` group before applying the email local-part rule, or strip only a name that is itself an email. Test with the real `ClaudeSwapAccount.displayName`, `CodexSwapAccount.displayName` and `CLIProxyHubCards.displayName` formats.
3. **minor** — `docs/providers/cliproxy-hub.md:45-47` ("One card per Claude or Codex account… Hub cards sit right after the local cards of their family"), `docs/providers/codex.md:60-61` ("remain separate cards… shares one card") and `docs/providers/claude.md:95-96` ("Each account gets a card…") still say each account has its own dashboard card. Fix: reword them as accounts/Customize entries, the way the edited paragraphs already do.
4. **minor** — Missing tests. Nothing covers: `WidgetDataStore.data(for:in:)` when an account has no matching descriptor (`WidgetDataStore+MergedAccounts.swift:12-14`); metric reorder and the Always Visible / On Demand split on a merged card through the base ids; the header Hide/Refresh fanning out to `memberIDs`. Fix: add focused tests for the store-level paths (the first two at least).
5. **minor** — `Sources/OpenUsage/Models/AccountMerge.swift:67-69`: bounded `.dollars` meters are summed without checking `currency`, even though the `.values` path checks it (:102). Two accounts whose Extra Usage meters use different currencies would add EUR to USD. The same branch fills bounded money/count bars as sum(used)/sum(limit), not as the "average fill" criterion 3 describes (the spec's "money sums" rule is followed). Fix: skip or leave unsummed a meter whose currency differs from the first (log it), and confirm the bounded-money fill rule with the owner.
6. **nit** — `Sources/OpenUsage/Views/WidgetRowView.swift`: 504 lines, over the ~500 LOC guideline in AGENTS.md. Fix: move the meter (or the tick overlay hookup) into its own small view.
7. **nit** — `Tests/OpenUsageTests/MergedProviderGroupTests.swift:117-124`: `try!` inside a non-throwing async test, so a missing descriptor crashes the test run instead of failing one test. Fix: mark the test `async throws` and use `try`.
8. **nit** — `Sources/OpenUsage/Stores/WidgetDataStore.swift:15`: `registry` went from `private` to internal only so the extension can look up account descriptors. Fix: if it fits, keep it private and put `data(for:in:)` in the main file, or add a narrow lookup.
